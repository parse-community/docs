# Objects

## The ParseObject

Data storage in Parse is centered around the `ParseObject`.  Each `ParseObject` holds key-value pairs of JSON-compatible data.  This data is schemaless, meaning you don't predefine keys. You set key-value pairs, and the backend stores them.

Example: tracking high scores for a game. A `ParseObject` might contain:

```csharp
// Example using C# and the Parse .NET SDK
// No need for Javascript example here
var gameScore = new ParseObject("GameScore");
gameScore["score"] = 1337;
gameScore["playerName"] = "Sean Plott";
gameScore["cheatMode"] = false;
```

Keys must start with a letter and can contain alphanumeric characters and underscores. Values can be strings, numbers, booleans, arrays, dictionaries, or other JSON-encodable types.

Each `ParseObject` has a class name (e.g., `GameScore`).  We recommend `PascalCase` for class names (`GameScore`) and `camelCase` for keys (`playerName`).

## Saving Objects

To save a `GameScore` to your Parse Server:

```csharp
ParseObject gameScore = new ParseObject("GameScore");
gameScore["score"] = 1337;
gameScore["playerName"] = "Sean Plott";
gameScore["cheatMode"] = false;  // You can add this now, no schema change needed.
await gameScore.SaveAsync();
```

After saving, you can check the Data Browser in your Parse app.  You'll see something like:

```jsonc
{
  "objectId": "xWMyZ4YEGZ",  // Unique ID, generated by Parse
  "score": 1337,
  "playerName": "Sean Plott",
  "cheatMode": false,
  "createdAt": "2024-10-27T14:30:00.000Z", // Automatically added
  "updatedAt": "2024-10-27T14:30:00.000Z"  // Automatically added
}
```

Key points:

*   You *don't* pre-configure a "GameScore" class.  Parse creates it *lazily* on first use.
*   `objectId`, `createdAt`, and `updatedAt` are automatically managed by Parse.  `objectId` is a unique identifier.  `createdAt` and `updatedAt` are timestamps. They aren't available until *after* the first save.

## Data Types

Besides `string` and `int`, Parse supports `double`, `DateTimeOffset` (use this instead of `DateTime` for better time zone handling), and `null`.  You can nest `Dictionary<string, object>` and `List<object>` for structured data.

Supported types:

*   String: `string`
*   Number: `double`, `int`, `long`, `float`, etc.
*   Boolean: `bool`
*   Array: `List<object>`
*   Object: `Dictionary<string, object>`
*   Date: `DateTimeOffset`
*   File: `ParseFile` ([Files](#files))
*   Pointer: Other `ParseObject` instances
*   Relation: `ParseRelation<T>` (where `T` is a `ParseObject` or subclass)
*   Null: `null`

Examples:

```csharp
int number = 42;
string str = "the number is " + number;
DateTimeOffset date = DateTimeOffset.Now;
List<object> list = new List<object> { str, number };
Dictionary<string, object> dictionary = new Dictionary<string, object>
{
    { "number", number },
    { "string", str }
};

var bigObject = new ParseObject("BigObject");
bigObject["myNumber"] = number;
bigObject["myString"] = str;
bigObject["myDate"] = date;
bigObject["myList"] = list;
bigObject["myDictionary"] = dictionary;
await bigObject.SaveAsync();
```

**Important:**  Avoid storing large binary data (images, documents) directly in `ParseObject` fields.  Use `ParseFile` instead (see documentation on [Files](#files)).

## Retrieving Objects

To retrieve an object by its `objectId`, use `ParseQuery<T>`:

```csharp
ParseQuery<ParseObject>? query = ParseClient.Instance.GetQuery("GameScore");
ParseObject? gameScore = await query.FirstOrDefaultAsync();
 // Or:  ParseClient.Instance.GetQuery("ParseObject>("GameScore");
ParseObject gameScore = await query.GetAsync("xWMyZ4YEGZ"); // Replace with the actual objectId
```

Access values using `Get<T>()`:

```csharp
int score = gameScore.Get<int>("score");
string playerName = gameScore.Get<string>("playerName");
bool cheatMode = gameScore.Get<bool>("cheatMode"); // Assuming it exists
```

Special fields are properties:

```csharp
string objectId = gameScore.ObjectId;
DateTimeOffset? updatedAt = gameScore.UpdatedAt; // Note: DateTimeOffset, not DateTime
DateTimeOffset? createdAt = gameScore.CreatedAt; // Note: DateTimeOffset
ParseACL acl = gameScore.ACL;  // Access Control List (see ACL documentation)
```

To refresh an object with the latest data from the server, use `FetchAsync()`:

```csharp
await gameScore.FetchAsync();
```

## Updating Objects

To update, modify the object and call `SaveAsync()`:

```csharp
// Create and save the initial object
var gameScore = new ParseObject("GameScore")
{
    { "score", 1337 },
    { "playerName", "Sean Plott" },
    { "skills", new List<string> { "pwnage", "flying" } },
};
await gameScore.SaveAsync();

// Update the object
gameScore["cheatMode"] = true; // Add a new field
gameScore["score"] = 1338;     // Update an existing field
await gameScore.SaveAsync();
```

Only changed ("dirty") fields are sent to the server.

### Counters

For counters, use `Increment()` for atomic updates (avoids race conditions):

```csharp
gameScore.Increment("score"); // Increment by 1
// Or:
gameScore.Increment("score", 10); // Increment by 10
await gameScore.SaveAsync();
```

### Lists

Atomic list operations:

*   `AddToList()` and `AddRangeToList()`: Append items.
*   `AddUniqueToList()` and `AddRangeUniqueToList()`: Add only if not already present (order not guaranteed).
*   `RemoveAllFromList()`: Remove all instances of given items.

Example:

```csharp
gameScore.AddRangeUniqueToList("skills", new[] { "flying", "kungfu" });
await gameScore.SaveAsync();
```

**Important:** You can't atomically *add* and *remove* items in the same `SaveAsync()` call.  Save between different list operation types.

## Lists (Atomic Operations)

`ParseObject` provides several methods for atomically modifying list-type fields.  "Atomic" means that these operations are guaranteed to be consistent even if multiple clients are modifying the same object simultaneously.  This prevents data corruption and race conditions.

**Available Operations:**

*   **`AddToList(string key, object item)`:** Appends a single `item` to the end of the list field identified by `key`.
*   **`AddRangeToList(string key, IEnumerable<object> items)`:** Appends multiple `items` to the end of the list field.
*   **`AddUniqueToList(string key, object item)`:** Adds a single `item` to the list *only if* the item is not already present in the list. The insertion position is not guaranteed.
*   **`AddRangeUniqueToList(string key, IEnumerable<object> items)`:** Adds multiple `items` to the list, but only those that are not already present.  Again, the order is not guaranteed.
*   **`RemoveAllFromList(string key, IEnumerable<object> items)`:** Removes *all* instances of each item in `items` from the list.

**Key Concepts:**

*   **Atomicity:** These operations are atomic at the *server* level.  This is crucial for data integrity when multiple clients might be updating the same list concurrently.
*   **Order (Append vs. Unique):**  `AddToList` and `AddRangeToList` preserve the order of insertion (they append to the end).  `AddUniqueToList` and `AddRangeUniqueToList` *do not* guarantee any specific order.  They only ensure uniqueness.
*   **`SaveAsync()` Requirement:**  You *must* call `SaveAsync()` after performing any of these list operations to persist the changes to the Parse Server.
* **Operation Mixing Restriction** You cannot mix addition operations, and removal operations in a single request.

**Examples:**

**1. Adding Items (Appending):**

```csharp
// Assuming gameScore is an existing ParseObject with a "skills" list field.
gameScore.AddToList("skills", "swimming");  // Add a single skill
await gameScore.SaveAsync();

List<string> newSkills = new List<string> { "climbing", "jumping" };
gameScore.AddRangeToList("skills", newSkills); // Add multiple skills
await gameScore.SaveAsync();
```

**2. Adding Unique Items (No Duplicates):**

```csharp
// Add "flying" only if it's not already in the "skills" list.
gameScore.AddUniqueToList("skills", "flying");
await gameScore.SaveAsync();

// Try to add "flying" and "swimming". "flying" will be skipped if present.
List<string> moreSkills = new List<string> { "flying", "swimming" };
gameScore.AddRangeUniqueToList("skills", moreSkills);
await gameScore.SaveAsync();
```

**3. Removing Items:**

```csharp
// Remove all instances of "swimming" from the "skills" list.
gameScore.RemoveAllFromList("skills", new List<object> { "swimming" });
await gameScore.SaveAsync();

// Remove multiple skills: all instances of "climbing" and "jumping".
List<string> skillsToRemove = new List<string> { "climbing", "jumping" };
gameScore.RemoveAllFromList("skills", skillsToRemove);
await gameScore.SaveAsync();
```

**4. Important:  Mixing Operations and `SaveAsync()`:**

You *cannot* combine add and remove operations in a single `SaveAsync()` call.  You *must* save between different types of list operations.  This is due to the underlying implementation of atomicity on the Parse Server.

```csharp
// CORRECT: Save between add and remove
gameScore.AddToList("skills", "stealth");
await gameScore.SaveAsync(); // Save after adding

gameScore.RemoveAllFromList("skills", new List<object> { "stealth" });
await gameScore.SaveAsync(); // Save after removing

// INCORRECT:  This will NOT work as expected!
gameScore.AddToList("skills", "stealth");
gameScore.RemoveAllFromList("skills", new List<object> { "swimming" });
await gameScore.SaveAsync(); // Only the *last* operation will be effective!
```

Also, you cannot mix addition operations.

```csharp
// INCORRECT:  This will NOT work as expected!
gameScore.AddToList("skills", "stealth");
gameScore.AddUniqueToList("skills", "swimming");
await gameScore.SaveAsync(); // Only the *last* operation will be effective!
```

**5. Combining with Other Updates:**

You *can* combine list operations with *other* non-list field updates in a single `SaveAsync()` call.

```csharp
// This is perfectly valid:
gameScore.AddToList("skills", "magic");
gameScore["score"] = 2000; // Update a non-list field
await gameScore.SaveAsync(); // Saves both the list update and the score update
```

**6. Data Types within Lists**
While the examples above use strings, lists in Parse can contain any of the supported Parse data types, including numbers, booleans, `DateTimeOffset` values, other `ParseObject`s (pointers), and even nested lists or dictionaries. However, be mindful of the size limits for individual objects and fields in Parse.

```csharp
    //List of ParseObjects
    ParseObject obj1 = new ParseObject("AnotherClass");
    ParseObject obj2 = new ParseObject("AnotherClass");

    myParseObject.AddRangeToList("listOfObjects", new List<ParseObject> { obj1, obj2 });
    await myParseObject.SaveAsync();

	//List of Dates
	myParseObject.AddToList("dates", DateTimeOffset.Now);
    await myParseObject.SaveAsync();
```

## Relational Data

Objects can relate to other objects, modeling one-to-many relationships.  A `ParseObject` can be a value in another `ParseObject`.  Parse stores the referred object once for consistency.

Example:  One `Post` has many `Comment`s.

```csharp
// Create the Post
var myPost = new ParseObject("Post")
{
    { "title", "I'm Hungry" },
    { "content", "Where should we go for lunch?" }
};

// Create the Comment
var myComment = new ParseObject("Comment")
{
    { "content", "Let's do Sushirrito." }
};

// Link Comment to Post (one-to-many)
myComment["parent"] = myPost; // "parent" is a pointer to myPost

// Save both (myPost doesn't need saving separately if it's new)
await myComment.SaveAsync();
```

Link by `objectId`:

```csharp
var myPost = new ParseObject("Post") // Or a Post subclass, or created with CreateObjectWithData
{
    { "title", "My New Post" },
    { "content", "This is the content." }
};
myComment["parent"] = myPost; // Assign the entire myPost object.
await myComment.SaveAsync();
```

By default, related objects aren't fetched. Fetch them explicitly:

```csharp
ParseObject post = myComment.Get<ParseObject>("parent");
await post.FetchIfNeededAsync(); // Fetch the related Post object
```

For many-to-many relationships, use `ParseRelation<T>`.  It's like `List<ParseObject>`, but scales better (doesn't require fetching all related objects at once).

Example:  A `User` likes many `Post`s.

```csharp
// Assuming you have a current user and a post object
ParseUser user = await ParseClient.Instance.GetCurrentUser();
ParseRelation<ParseObject> relation = user.GetRelation<ParseObject>("likes"); // "likes" is the relation field
relation.Add(post);  // Add the post to the user's "likes"
await user.SaveAsync();
```

Remove from the relation:

```csharp
relation.Remove(post);
await user.SaveAsync();
```
To Query:
```csharp
var relatedObjects = await relation.Query.FindAsync();
```
or
```csharp
var query = from post in relation.Query
            where post.CreatedAt > DateTimeOffset.Now - TimeSpan.FromDays(10)
            select post;

//or

var query = relation.Query
.WhereGreaterThan("createdAt", DateTimeOffset.Now - TimeSpan.FromDays(10));
```

## Subclasses (Recommended)

While `ParseObject` works, subclasses offer:

*   **Terseness:**  Less verbose code.
*   **Extensibility:**  Add custom logic.
*   **Type-safety:**  Fewer runtime errors.
*   **IntelliSense:**  IDE code completion.

Subclassing is *optional* but highly recommended.

**Without Subclasses:**

```csharp
var shield = new ParseObject("Armor")
{
    { "displayName", "Wooden Shield" },
    { "fireproof", false },
    { "rupees", 50 }
};

Console.WriteLine(shield.Get<string>("displayName"));
shield["fireproof"] = true;
shield["rupees"] = 500;
await shield.SaveAsync();
```

**With Subclasses:**

```csharp
// Using object-initialization syntax:
var shield = new Armor
{
    DisplayName = "Wooden Shield",
    IsFireproof = false,
    Rupees = 50
};

Console.WriteLine(shield.DisplayName);
shield.IsFireproof = true;
shield.Rupees = 500;
await shield.SaveAsync();
```

### Creating a Subclass

1.  **Inherit:** Subclass `ParseObject`.
2.  **`ParseClassName` Attribute:** Add `[ParseClassName("YourClassName")]`.
3.  **Default Constructor:**  Must have a public, parameterless constructor. *Don't* modify `ParseObject` fields in this constructor.
4.  **Register:** Call `ParseClient.Instance.RegisterSubclass(YourClass)` *AFTER* `ParseClient.Initialize()`.

Example (`Armor` subclass):

```csharp
// Armor.cs
using Parse;
using Parse.Infrastructure; //If you want to use ServerConnectionData

[ParseClassName("Armor")]
public class Armor : ParseObject
{
    // Default constructor is required.
    public Armor() { }
}

// App.xaml.cs (or wherever you initialize Parse)
public App()
{
    InitializeComponent();

    MainPage = new AppShell();
   
    // Initialize Parse Client.  (See initialization documentation)
    if (!InitializeParseClient())
    {
        // Handle initialization failure
        Console.WriteLine("Failed to initialize Parse.  Check your keys and internet connection.");
    }
     ParseClient.Instance.RegisterSubclass(Armor); // Register AFTER Initialize
    ParseClient.Instance.RegisterSubclass(Post); // Register all used custom classes.
    ParseClient.Instance.RegisterSubclass(Comment);

}
```

### Properties and Methods

Add properties for fields using `GetProperty<T>()` and `SetProperty<T>()`.  Use the `[ParseFieldName("fieldName")]` attribute.

```csharp
// Armor.cs
[ParseClassName("Armor")]
public class Armor : ParseObject
{
    public Armor() { }

    [ParseFieldName("displayName")]
    public string DisplayName
    {
        get => GetProperty<string>();
        set => SetProperty(value);
    }

    [ParseFieldName("fireproof")]
    public bool IsFireproof
    {
        get => GetProperty<bool>();
        set => SetProperty(value);
    }
     [ParseFieldName("rupees")]
    public int Rupees
    {
        get => GetProperty<int>();
        set => SetProperty(value);
    }
      // Define the relation to ArmorAttributes (assuming you have an ArmorAttribute class)
    [ParseFieldName("attribute")]
    public ParseRelation<ArmorAttribute> Attributes
    {
        get => GetRelation<ArmorAttribute>("attribute"); // Use GetRelation for relations.
    }
}
```

Now you can use `armor.DisplayName`, `armor.IsFireproof`, etc., with compile-time checking and IntelliSense.

Add custom methods for logic:

```csharp
// In Armor.cs
public void TakeDamage(int amount)
{
    this.Increment("durability", -amount); // Assuming you have a "durability" field
    if (this.Durability < 0)
    {
        this.IsBroken = true;  // Assuming you have an "IsBroken" field
    }
}
```

### Initializing Subclasses

Create new instances using constructors:

```csharp
var myArmor = new Armor { DisplayName = "Steel Shield", Rupees = 100 };
```

For existing objects (by `objectId`):

```csharp
var armorReference = ParseClient.Instance.CreateWithoutData<Armor>("existingObjectId");
```

### Queries on Subclasses

Use `ParseQuery<T>` for subclass-specific queries:

```csharp
// Get armors the user can afford (assuming a "Player" subclass of ParseUser)
var query = from armor in ParseClient.Instance.GetQuery("Armor")
            where armor.Rupees <= ((Player)ParseClient.Instance.GetCurrentUserResult).Rupees
            select armor;
IEnumerable<Armor> affordableArmors = await query.FindAsync();

//or

var query = ParseClient.Instance.GetQuery("Armor")
.WhereLessThanOrEqualTo("rupees", (await ParseClient.Instance.GetCurrentUser()).Rupees);
```

The `ParseQuery` LINQ provider understands `[ParseFieldName]` attributes, enabling strongly-typed queries.
